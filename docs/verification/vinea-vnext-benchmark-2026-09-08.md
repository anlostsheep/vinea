# Vinea vNext 单题对照

日期：2026-09-08。这是一次定位问题的小样本试跑，不是效率认证。

## 条件

- 同一个 `normalizeTags` 实现需求、相同初始代码、外部验收断言、Node/Git/CLI。
- 配置模型 `gpt-6-astra`，推理级别 `xhigh`，standard 质量，单 agent。
- 独立测试仓库和宿主配置目录；禁止提交、部署、安装依赖和修改无关文件。
- 每次模型运行上限 300 秒。缓存、服务端波动和少量并行验收活动未被完全控制。
- 基准使用冻结的新内核包，不把之后的身份指引/错误提示修正混入结果。

## 结果

| 条件 | 已计量总 tokens | 运行时间 | 外部业务验收 | Vinea 交付状态 |
|---|---:|---|---|---|
| 不使用框架 | 276,903 | 95.6 秒 | 通过 | 不适用 |
| 旧 Vinea | ≥924,649 | 300 秒超时 | 未通过，未修改业务源码 | 未交付 |
| 新内核，默认 workspace 沙箱 | 724,549 | 212.7 秒 | 通过 | `.git/vinea` 无写权限，未建立任务；不算协议成功 |

## 可以与不可以得出的结论

1. 在这个小任务上，直接执行的成本最低。**没有证据证明新内核更省 token**。
2. 新内核在预算内完成了业务验证并保存正式交付，而旧流程未完成业务实现。
   这说明本次流程进展不同，不足以推出普遍成功率提升或 token 降幅。
3. 正式回执先于会话中断保存；随后同一真实宿主仅用两个只读查询恢复出结果，
   没有重新实现或验证。该恢复另花 58.8 秒，未混入上面的原始 300 秒试跑。
4. 默认沙箱中的初试暴露了真实接入缺口；业务通过不能掩盖 Vinea 记录未建立。
   后续精确目录权限试验保留了其他 Git 文件的只读限制，没有关闭沙箱。
5. 这里只有一个业务任务，没有重复采样或复杂项目/多次接续对照。不能据此
   宣传更省 token、更高成功率，或用缓存差异推算成本优势。

安装、权限排查、控制器澄清和后续恢复不计入原始试跑表；不能把它当作完整
用户旅程的耗时。四个夹具的初始 Git tree 哈希相同，差异条件和干预分别保留。
